---
name: grill-me
description: Clarify ambiguous feature requirements before writing a design spec, using focused questions and repository evidence.
---

Inspect available project context before asking questions. Ask one material question at a time, with two or three concise options when useful. Use the actual user-input tool exposed by the client and its documented schema; if none is available, ask directly in chat. Never invent a tool name or parameter. Do not re-ask decisions already supplied by the user. Choose routine internal engineering defaults autonomously and document them briefly.

Resolve material uncertainty about user-visible behavior, scope, interfaces and tradeoffs. Keep the interview proportional to the task. Write the design spec under docs/superpowers/specs/ and present its path and key decisions. Stop for explicit spec approval before decomposing implementation tasks. Existing explicit approval counts; elapsed time does not.
